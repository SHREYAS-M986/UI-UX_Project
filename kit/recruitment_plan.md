# Participant Recruitment Plan & Screener
**Project**: AccessAudit — Accessibility Audit Tool for Developers  
**Target Sample Size**: Minimum 5 participants (following Nielsen's 5-user heuristic rule for qualitative usability testing).

---

## 1. Target User Cohorts & Stratification
To ensure broad workflow coverage, participants must be distributed across four key software roles:
1. **Cohort 1: Beginner / Junior Front-End Developer** (1 participant)
   - Profile: 0.5–2 years experience; builds UI components; relies heavily on linters and tutorials.
   - Purpose: Test whether plain-language explanations and inline snippets allow rapid remediation without senior assistance.
2. **Cohort 2: Mid-to-Senior Front-End Engineer** (2 participants)
   - Profile: 3–7 years experience; works in React/Vue/Angular; faces strict sprint deadlines.
   - Purpose: Test triage efficiency, impact-to-effort ranking, and code copy-paste ergonomics.
3. **Cohort 3: UI/UX Designer & Prototyper** (1 participant)
   - Profile: Design systems specialist; works with Figma and CSS variables.
   - Purpose: Evaluate visual hierarchy, color palette contrast comprehension, and glassmorphism clarity.
4. **Cohort 4: Lead Developer / QA Automation Specialist** (1 participant)
   - Profile: 5+ years experience; manages Cypress/Playwright suites and sprint reporting.
   - Purpose: Test reporting export capabilities, multi-page metrics, and overall compliance verification.

---

## 2. Participant Screening Questions
- Screener Q1: *"Do you write, review, or test web user interfaces as part of your primary work or academic studies?"* (Must be YES).
- Screener Q2: *"Have you ever run an automated web audit tool (e.g., Lighthouse, axe DevTools, or WAVE)?"* (Must be YES).
- Screener Q3: *"Can you dedicate approximately 20–25 minutes to an unassisted usability evaluation session over Google Meet or in person?"* (Must be YES).

---

## 3. Remote Testing Logistics
- Participants access the live web app directly: `https://access-audit-roan.vercel.app`.
- Session hosted via screen-share (Google Meet / Zoom) or conducted in a computer lab setting.
- Observer records screen audio, task start/stop times with a stopwatch, and logs observations into `evidence/research_data.xlsx`.
